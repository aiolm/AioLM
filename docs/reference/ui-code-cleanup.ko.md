# 사용하지 않는 UI 코드 정리

기준 소스 `ee81a7f`에서 앱 진입점과 import·re-export·동적 import, 테스트·스크립트의 참조를 조사했다. 삭제 후보를 개별 검토한 뒤 현재 모델 설정 모달에 연결되지 않는 구현을 제거했다.

## 정리 범위

- 구형 `Tuning.tsx` 페이지, 전용 탐색·프리셋·원시 입력·서버 옵션 화면과 저장/재시작 컨트롤러를 제거했다. 해당 구현만 검사하던 UI 테스트 5개와 비동기 비교 유틸리티의 직접 검사도 제거했다. 현재 모달의 `DraftTuningEditor`, `DraftAdvancedEditor`, 엔진별 schema 편집기 및 공유 튜닝 필드는 유지한다.
- 연결되지 않는 `RuntimeLoadingProfiles` 화면과 `ActionMenu` 컴포넌트, 이들 화면만 검사하던 테스트를 제거했다. 실제 프로필 선택·저장·이전과 Windows 경로 표시는 현재 모달 및 관련 검사에서 유지한다.
- 앱에서 호출하지 않는 개발용 curl 예제 유틸리티, 모델 행 이벤트 보조 함수, 설정 export 예제와 이 구현만 검사하던 코드를 제거했다. 실행 중인 개발자 화면, 모델 행, 설정 백업 기능은 각자의 현재 구현을 그대로 사용한다.
- 구형 페이지의 탭·검색 메타데이터와 `advancedOnly` 표시, 미사용 탐색 아이콘 5개, 전용 CSS를 제거했다. 공유 CSS 규칙에서는 삭제한 화면의 selector만 뺐다. 현재 필드 설명·별칭·기본값·요청/서버 옵션 구분은 보존한다.
- 삭제된 직접 검사에 대응하는 npm 명령과 테스트 목록, 오래된 문서의 화면 안내를 정리했다. 의존성 및 lockfile은 변경하지 않았다.

공개 API·저장 데이터 계약, 이전 데이터 판독, 다른 OS의 코드, 컴파일러 선언 파일, 라이선스와 검증 이력은 삭제 대상에서 제외했다. 특히 `vite-env.d.ts`는 import가 없는 컴파일러 환경 선언이므로 보존한다. 사용자 설정·모델·대화, 기존 `tmp/` 자료와 빌드 결과도 정리 대상으로 취급하지 않았다.

## 확인 결과

- 정리 후 앱 진입점 그래프에서 연결되지 않는 실행 TS/TSX 모듈은 없다. 이 결과는 공개 API의 개별 export나 다른 OS 코드까지 불필요하다고 판정한다는 뜻은 아니다.
- UI **201개 파일·2,187개 테스트 통과**. 기존 207개 파일·2,268개에서 삭제된 구형 UI 전용 테스트 6개 파일·80개 검사와 구형 프로필 화면 검사 1개가 빠졌다. 현재 기능 검사를 skip하거나 실패 기준을 낮추지 않았다.
- `test:direct`, `typecheck`, `lint`, production 프런트엔드 `build` 통과. 직접 검사에 i18n·설정 schema·런타임 유틸리티·저장·경로·CSS 검사가 포함된다. 기존 `CustomSelect`의 effect 의존성 린트 경고 1개, jsdom의 canvas/pseudo-element 안내와 큰 workbook 청크 안내는 남아 있다.
- 실제 Windows Tauri 개발 창에서 Strata와 llama.cpp의 런타임 선택 → 프로필 선택 → 옵션 화면을 열었다. Strata의 실제 옵션 목록과 llama.cpp의 공유 필드 화면을 확인했다. 임시 런타임 선택을 버리고 닫은 뒤 전체 설정 파일·프로필 7개·대화 파일 8개의 해시가 시작 전과 같았다. 이번 정리는 엔진 추론·설치 패키지 검증을 새로 수행한 작업이 아니다.

삭제 전 파일별 SHA-256과 참조 감사, 검사 로그, 실제 창 확인 자료는 `tmp/strata-dev/cleanup-*`에 보관하고 커밋하지 않는다. Antigravity의 읽기 전용 감사는 실제 사용량 제한으로 실패했으므로, 동일 실패를 성공으로 기록하지 않고 직접 참조 감사를 수행했다.

## 후속 참조 감사

추가 import·export·동적 이미지 경로·빌드·테스트 참조 감사에서 구형 Qwen 프리셋 표와 검색 함수, 호출되지 않는 기본값 표시 함수 `serverDefaultLabel`, 이전 로딩 프로필의 저장 함수 `writeLoadingProfiles`를 제거했다. 이전 데이터의 `readLoadingProfiles`·검증·이전 경로는 보존한다. `qwenDefaults.ts`의 남은 메타데이터는 실제 앱에서 사용하지 않았고, 채팅이 사용하던 다섯 fallback 값만 `chatRequestFallbacks.ts`로 옮겼다. 값과 사용자 설정 우선순위는 바꾸지 않았다.

구형 상수 자체를 다시 확인하던 직접 검사 18개 assertion은 제거했다. 실제 요청 본문·관리 인자 거부·별칭·추론 옵션 검사는 같은 합성 입력으로 유지한다. 참조가 없는 `public/favicon.png`도 제거했으며, 브라우저 기본 `favicon.ico`, 현재 브랜드 이미지, 네이티브 아이콘과 라이선스 파일은 보존한다. production build에서 중복 PNG가 제외되고 현재 이미지가 남는 것을 확인했다.

이 후속 변경에서 UI **201개 파일·2,189개 테스트**, 관련 채팅 검사 **10개 파일·161개 테스트**, 직접 검사 21개 스크립트·typecheck·build·lint가 통과했다. 기존 린트 경고 1개와 jsdom·큰 workbook 청크 안내는 남아 있다. 설정 파일 전체·프로필 7개·대화 파일 8개의 해시도 시작 전과 같다. 변경 후 새 엔진 추론이나 설치 패키지 검증을 수행했다는 판정은 아니다.

Rust 모듈·내장 provider 리소스·플랫폼 및 설치 스크립트는 `include_str!`, 테스트 discovery, CI·배포·문서의 실제 사용처가 확인돼 삭제하지 않았다. 정적 미참조만으로 공개 API·저장 계약·다른 OS 코드가 불필요하다고 판정하지 않는다. 후속 감사와 검사 원본은 `tmp/efficiency-review/`에 남긴다.

## 내부 함수와 연결 코드 추가 정리

실제 앱의 호출 경로를 다시 추적해 테스트에만 연결된 `useSessionActivity`와 전용 구독·알림 코드를 제거했다. 여러 세션의 사용 중 상태를 기록하고 실행·종료를 막는 동기 검사는 보존한다. 호출처가 없는 내부 `migrateLegacyKey`도 제거했다. 앱 시작 시 실행되는 `storageMigration`, IndexedDB와 localStorage의 기존 판독·fallback·삭제, 저장 데이터 형식은 바꾸지 않았다. 이 두 함수는 배포 패키지의 공개 export나 문서화된 API가 아니다.

호출되지 않는 `useModelContextLimit` 래퍼를 제거하고, 실제 사용하는 훅을 `useSelectedModelMetadata.ts`로 옮겨 import를 갱신했다. 선택 모델의 metadata 조회와 오래된 응답 무시는 그대로다. 벤치마크 desktop 연결부에서도 사용처가 없는 별칭 네 개와 낡은 mock 항목을 제거했다. 현재 공유 화면이 사용하는 업로드·조회·Retry·승인 후 정리와 공통 outbox 저장·전송 기능, 공개 benchmark 계약은 유지한다.

세션·저장·채팅·프로필 관련 **6개 파일·189개 검사**, 모델 설정·공유·outbox 관련 **6개 파일·173개 검사**가 통과했다. 추가로 초기 대화 복원에서 불변 데이터의 직렬화 비교 4회를 없애고, 실제 수정·삭제·진행 중 대화 보존 검사를 확인했다. 자원 추정의 불변 설정 처리와 공유 요청 준비의 중복 직렬화까지 반영한 최종 전체 UI **203개 파일·2,214개 검사**와 타입·production build·lint·직접 검사가 통과했다. 구독 hook 전용 테스트 한 개를 제거하고 초기 복원·설정 재사용·공유 바이트 계약의 회귀 검사를 추가했으며, 현재 기능 검사를 skip하지 않았다. 기존 린트 경고 한 개는 유지하며 설정 파일 전체·프로필 7개·대화 파일 8개 해시는 같다.

Python runtime-adapter·모델 복구·portable helper와 실제 Rust 호출자도 추가 검토했다. 이 범위에서는 삭제할 미사용 파일을 입증하지 못했으며, 내장 리소스·운영자 도구·보안 및 플랫폼 검사를 유지했다. wheel 캡처의 반복 해시·누적 합산과 지침 파일의 과도한 버퍼 용량은 따로 개선하고 결과 보존을 확인했다. 이번 검사에서 새로 만든 Python bytecode만 제거했다. 기존 임시 자료·빌드·설정·이력과 라이선스는 보존하며, 전체 프로젝트의 검토가 끝났다는 판정은 아니다.

native 이력 스캔의 중복 경로 생성과 digest 집합의 불필요한 정렬도 제거했다(`1f44223`). 캐시 초과 시 모델 정보를 전부 버리던 동작과 Python probe 출력의 과도한 보관은 각각 개선했다(`845d2f7`, `58bc9b5`). 실제 반환 결과·오류·변조 거부·데이터 보존을 검사했으며, 자세한 측정 범위와 메모리·처리 시간의 교환 비용은 [효율 검토 기록](efficiency-review.ko.md)에 남긴다. 최종 Python 21개·Rust 라이브러리 1,158개·CLI 15개와 원본 소스의 직접 어댑터 통합 검사 두 개가 통과했다. 실행 중인 GUI 잠금으로 실패한 Cargo 통합 실행과 직접 검사 결과는 구분한다.

빌드·패키징 helper 다섯 개는 실제 npm·CI·OS·운영 문서의 호출에 필요해 보존했다. Linux release에서 중복 실행하던 CLI 사전 빌드 한 줄은 제거했다(`24efa45`). packaging 자체의 단일 CLI 빌드와 전체 검사는 유지하며, 로컬 workflow 판독·기존 Node packaging 검사 3개를 통과했다. 실제 Linux CI·설치 실행으로 기록하지 않는다.

Strata 준비·모델 미선택 probe의 중복 JSON 해석을 줄이고, 이 변경으로 사용하지 않게 된 JSON 래퍼와 setup 지역 변수도 제거했다(`b8c9e4e`). 설정·필수 파일은 다시 읽고 확인하며, 다른 모델 설정의 독립 검증은 유지한다. 설정 교체로 서로 다른 정보를 섞어 반환하던 경로는 거부하도록 고쳤다. Python 27개 검사와 정상 출력·오류 10개 사례의 독립 비교가 통과했으며 실제 엔진 추론 검증과 구분한다.

compatibility wheel 생성의 불필요한 ZIP metadata 복사를 제거했다(`a37c415`). 합성 101개 파일의 전체 ZIP·내용·속성·라이선스·RECORD와 오류를 비교하고 기존 Python 15개 검사를 통과했다. 별도의 해시 캐시는 전체 호출 측정에서 추가 복잡성을 정당화할 이점이 확인되지 않아 제외했다. compatibility 도구 네 파일은 CI·운영 문서·기존 검사에 실제로 연결돼 있어 보존했다.

MLX 호환성 확인 도구 `check_*.py` 6개도 실제 운영 명령과 함수·입력·assertion의 흐름을 추적했다. 토큰 처리·미디어 순서·attention cache·오디오 padding·동시 실행은 서로 다른 회귀 조건이므로 반복처럼 보이는 호출을 제거하지 않았다. 구문 검사 6개와 관련 독립 Python 검사 15개가 통과했다. 현재 Windows Python에는 MLX가 없어 설치된 MLX 함수의 실제 호출은 실행하지 않았으며, 대상 환경에서 수행할 [운영 명령](macos-validation-recovery.ko.md)은 보존했다. 이번 검사에서 새로 생성한 bytecode만 제거했다.

스냅샷 manifest 값 재사용 후보는 비정상 추가 정보를 준비 완료로 잘못 판정하는 결함이 실제로 재현돼 제거했다(`e2b2b39`). 관찰용 구조체·원문 보관·내부 래퍼를 걷어내고 필요한 기존 JSON 검증을 복원했다. 최상위·파일 항목의 6개 회귀 사례와 정상 추가 정보·필터를 검사했고, 관련 22개·전체 Rust 라이브러리 1,159개·CLI 15개·fmt·Clippy·원본 소스의 직접 어댑터 통합 검사 2개가 통과했다. 기존 검사와 데이터 계약을 보존했으며, 자세한 재현·비교 근거와 검증 범위는 [효율 검토 기록](efficiency-review.ko.md)에 남긴다.
