# 중복 조작 통합

모델 설정과 추론 엔진·앱 설정의 중복 6건(D01–D06), 범위가 겹치는 기능 3건(O01–O03)을 정리했다. 사용자 데이터나 저장 형식을 바꾸는 작업은 아니다. 기준 소스는 `78dcfcc6e9da6a6408b7d0b107b93608c85f9ccf`다.

## 변경과 확인

| 항목 | 변경된 동작 | 보존한 기능과 확인 근거 |
| --- | --- | --- |
| D01 옵션 초기화 | 광범위 초기화는 프로필 상단 한 곳에서 실행한다. 하위 튜닝의 전체 초기화 버튼을 제거했다. | 필드별 초기화는 유지한다. 모달 검사에서 필드 초기화·광범위 초기화·대화 지침과 모델 연결 보존을 확인했다. Windows GUI에서도 단일 버튼과 보조 모델 경로 보존을 확인했다. |
| D02 명령 가져오기 | llama.cpp는 기존 typed 설정에 적용하는 명령 붙여넣기만 제공한다. 다른 엔진은 해당 런타임의 schema/명령 구문 선택 경로를 사용한다. | 명령 미리보기·도움말 탐색·미확인 인자 안내를 보존했다. 비어 있는 llama schema 검색 폼도 표시하지 않는다. 실제 GUI에서 `--ctx-size 8192 --temp 0.4`의 두 값 적용과 컨텍스트 입력 반영을 확인했다. |
| D03 드래프트 모델 | 목록 제안과 직접 경로 입력을 하나의 편집 가능한 선택기에 합쳤다. 추측 디코딩 영역의 중복 경로 입력을 제거했다. | 임의 경로·Unicode·공백과 목록 선택을 유지한다. 화면 표시와 저장 경로를 구분해 Windows 긴 경로 접두사도 보존한다. 합성 프로필 저장 검사 및 실제 GUI 초안의 경로 읽기로 확인했다. |
| D04 비전 프로젝터 | 목록과 경로 입력을 하나의 편집 가능한 선택기로 제공한다. | 목록 밖 파일 경로와 분할 모델의 선택 제한을 유지한다. D03과 같은 저장 검사 및 실제 GUI 경로 읽기로 확인했다. |
| D05 취소 | 활성 로컬 취소 버튼이 작업의 취소를 맡으면 전역에는 진행 상황만 보인다. 특정 작업 ID 허용 목록을 제거했다. | 작업 화면 이탈·언마운트·비활성·숨겨진 단계·접힌 영역·inert 상태에서는 전역 취소를 복구한다. 모달과 앱이 같은 등록 범위를 공유한다. 기존 작업과 새 작업 ID 5종, 미래 ID, 취소 중 상태, 모달 관리자 복귀를 통합 모의 검사했다. 실제 설치·등록을 취소하는 Windows 흐름을 이번에 새로 실행했다는 뜻은 아니다. |
| D06 런타임 점검 | 설치 버전 행이 점검의 단일 입구이고 결과 카드는 결과만 표시한다. | 같은 행에서 다시 점검할 수 있다. 자동 검사에서 정확한 backend/build의 반복 호출을 확인했다. Windows의 실제 Vulkan 설치본에서도 사용 가능 결과와 중복 버튼 부재를 확인했다. |
| O01 드래프트 장치 | 런타임·GPU 화면 한 곳에서 감지된 GPU 선택과 장치 이름 직접 입력을 전환한다. | `gpu.draft_gpu_id`와 우선 적용되는 `spec_draft_device` 저장 계약은 그대로다. 열기만으로 값을 바꾸지 않는다. 직접 지정에서 장치 선택으로 명시적으로 전환할 때 수동 값만 비운다. `none`, 여러 이름, 빈 값의 기존 GPU 선택 적용을 검사했다. 실제 GUI에서 키보드 전환과 `none` 입력도 확인했다. |
| O02 앱 설정 초기화 | 초기화 입구 하나에서 전체·채팅 표시·서버 동작·화면/테마·고급·알림을 선택하고 확인한다. 백업 카드의 초기화 버튼 5개를 제거했다. | 각 범위의 기존 환경설정 키만 바꾼다. 서버 범위는 자동 실행·상태 확인 간격 등 기존 `AppPreferences.server`이며, 네이티브 엔진 설정과 창 닫기 동작은 포함하지 않는다. 범위 선택·취소 시 무변경, 확인 후 해당 키만 변경을 검사했다. 실제 GUI에서는 6개 범위 표시·선택·취소를 확인했다. 실제 사용자 환경설정을 초기화하지 않았다. |
| O03 직접 편집 | 기본 화면은 항목별 조정이다. 전체 실행 인자와 요청 JSON은 명시적인 직접 입력 모드에서만 표시한다. | 모드 전환만으로 저장값을 바꾸지 않는다. 미등록·반복 인자와 Unicode 값을 보존한다. 잘못 입력한 값이 있으면 현재 입력 화면에서 수정하도록 안내해 숨겨진 오류를 만들지 않는다. 모의 검사와 실제 GUI에서 JSON 오류 유지·수정·항목별 화면 복귀를 확인했다. |

## 검증 범위

- 최종 소스의 UI 검사: **207개 파일, 2,268개 통과**. Windows 긴 경로 보존과 모달 취소 통합 검사까지 포함하며, typecheck·production frontend build도 통과했다.
- 변경된 TypeScript/TSX의 ESLint 및 4개 언어 i18n 검사 통과. 기존 jsdom의 canvas/pseudo-element 미구현 안내와 큰 workbook 청크 빌드 안내는 남아 있으며 실패를 제외하거나 기준을 낮추지 않았다.
- 실제 Windows Tauri 개발 창에서 위 표의 GUI 항목을 확인했다. GPU 화면과 초기화 범위 확인창은 스크린샷도 직접 확인했다. 새 설치 패키지나 production 바이너리를 이번 UI 작업에서 검증한 것으로 표시하지 않는다.
- 실제 점검 대상은 Vulkan `b11035`, 보고 버전 `0.4.1-dev(11035)`이며 설치 목록의 revision은 `bbd488c42`다. `llama-server.exe`의 SHA-256은 `f4f9cf1d5b5a9bc5939d4932444dabef5cf2e1d64145ba87ebe958891ca3a0cc`다. 이 실행 파일의 식별값을 전체 런타임 번들이나 모델 추론의 검증으로 확대하지 않는다.
- 실제 사용자 데이터에는 저장·초기화·추론을 실행하지 않았다. 임시 모델/옵션 초안을 버린 뒤 **전체 설정 파일·프로필 7개·대화 파일 8개**의 해시가 시작 전과 같음을 확인했다. 런타임 점검은 별도의 읽기 전용 실행 파일 점검이다.
- 임시 증거는 `tmp/strata-dev/duplicate-fixes-*`에 보관하며 커밋하지 않는다. 새 엔진 ID 분기, API/설정 migration, 의존성·lockfile·Rust 변경은 없다.

서로 다른 대상의 중지/언로드, 프로필 저장/저장 후 실행, 대화 지침의 서로 다른 적용 범위, 프로젝트 저장/적용, 선택 결과/전체 결과 내보내기는 유지한다. 같은 이름이라는 이유로 다른 기능을 삭제하지 않는다.
