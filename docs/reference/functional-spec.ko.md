# AioLM 기능 명세서

AioLM은 `llama.cpp` 기반의 로컬 AI 모델을 설치·실행하고, 채팅과 성능 측정을 제공하는 Windows x64 데스크톱 앱이다. 아래는 현재 저장소의 문서와 구현을 기준으로 정리한 주요 기능이다.

| ID | 기능 | 주요 동작 |
| --- | --- | --- |
| F01 | 모델 실행 | 지정 폴더의 GGUF 모델을 검색·조회·삭제한다. 모델 선택 후 같은 화면에서 런타임·프로필·컨텍스트·GPU 설정을 확인하고 실행한다. |
| F02 | 모델 다운로드 | Hugging Face에서 모델과 파일을 검색하고 다운로드한다. 진행 상태 확인과 다운로드 취소를 지원한다. |
| F03 | 런타임 관리 | CPU·Vulkan·ROCm·CUDA·SYCL·OpenVINO 런타임을 설치·선택·제거한다. ZIP 가져오기·내보내기와 출처 확인 후 PR 빌드 설치를 지원한다. |
| F04 | 서버·세션 관리 | 선택한 모델과 런타임으로 서버를 시작·중지하고 모델을 언로드한다. 여러 실행 세션의 상태를 조회하고 개별 제어한다. |
| F05 | 채팅 | 모델 응답을 실시간으로 표시하고 생성을 중지한다. 대화를 로컬에 저장하고 대화 생성·전환·삭제를 지원한다. |
| F06 | 첨부·문서 활용 | 이미지와 문서를 첨부하고, 문서 검색과 임베딩을 활용해 관련 내용을 대화에 반영한다. 이미지·임베딩 기능은 선택한 모델과 런타임의 지원 여부에 따른다. |
| F07 | 실행 설정 | 모델을 선택하거나 실행할 수 있는 화면에서 공통 설정 창을 열고, 선택한 프로필의 런타임·GPU·튜닝·LoRA·비전 설정을 편집한다. 옵션을 개별 또는 전체 초기화하고 서버 설정 변경을 저장·재시작한다. 모델마다 마지막으로 저장한 런타임·GPU·튜닝·어댑터 구성을 복원한다. |
| F08 | 프로필·프로젝트 | 실행 옵션은 항상 선택된 프로필 안에서 편집한다. 새 설치에는 기본 프로필 하나만 생성한다. 모든 프로필을 기본으로 지정할 수 있으며, 지정된 기본 프로필만 삭제할 수 없다. 다른 프로필을 삭제하면 사용하던 모델과 세션에 기본 프로필의 설정과 프롬프트를 적용한다. 칩 선택은 설정 미리보기이며, 명시적으로 적용하면 대상에 즉시 저장하고 창을 유지한다. 편집 중에도 프로필 이름과 선택 상태를 유지하고, 저장 시 프로필과 대상 설정을 함께 갱신한다. 새 프로필 저장·이름 변경·삭제·저장된 설정 복원을 지원한다. 프로젝트별 설정과 프로필 연결 정보를 관리하고 프로젝트 JSON을 가져오거나 내보낸다. |
| F09 | 벤치마크 | 전용 `llama-server`에서 입력 길이·생성 길이·동시 요청 수별 성능을 측정한다. PP/TG, 첫 토큰 지연, 토큰당 지연, 전체 지연, 프로세스 RAM을 표시하고 반복 측정·취소·이력 조회·CSV 내보내기를 지원한다. |
| F10 | API·게이트웨이 | 로컬 API 주소와 호출 예제를 제공한다. Anthropic 호환 및 Responses API를 제공하는 게이트웨이를 시작·중지한다. |
| F11 | MCP 연동 | MCP 서버를 등록·수정·삭제하고 도구 목록을 조회한다. 승인 정책에 따라 채팅에서 도구를 실행한다. |
| F12 | 진단·환경 설정 | 실행 상태와 진단 정보를 확인한다. 한국어·영어·일본어·중국어, 화면 테마, 서버 동작 등을 설정하고 환경 설정을 가져오기·내보내기·초기화한다. |

**기본 사용 흐름:** 모델 준비 → 모델 실행 화면에서 선택 → 런타임·프로필·설정 확인 → 실행 → 채팅 또는 API 사용. 필요한 런타임은 실행 화면의 ‘런타임 관리’에서 설치하고 돌아온다.

**주요 동작 조건**

- 모델·런타임 다운로드와 외부 서비스 연동에는 네트워크 연결이 필요하다.
- 서버 설정 변경은 적용 및 재시작 후 반영하며, 프로젝트 설정 적용은 서버가 중지된 상태에서 수행한다.
- 실행 중 다른 모델을 선택하면 중지 여부를 확인하며, 전환 후 새 모델은 직접 실행한다. 미저장 입력은 저장 또는 버리기 후 전환하며 잘못된 입력은 저장·실행을 막는다.
- 저장된 프로필은 공유하고 모델별 마지막 구성은 별도로 보관한다. 저장된 설정이 없는 모델에는 지정된 기본 프로필의 값과 프롬프트를 사용한다. 기본 프로필이 비전 프로젝터·드래프트 모델·LoRA 같은 모델별 항목을 포함하면 해당 값도 적용한다. 프로젝트를 명시적으로 적용하면 해당 프로젝트 구성을 우선한다. 설치되지 않은 런타임은 자동 대체하지 않고 재선택·설치를 안내한다.
- 프로필 미리보기는 편집값이나 적용 상태를 바꾸지 않는다. 수정한 옵션은 선택된 프로필의 미저장 변경으로 표시하며, 모든 옵션과 프롬프트가 저장된 값으로 돌아오면 편집 중 표시를 해제한다. 잘못된 입력은 수정할 때까지 오류 상태를 유지한다. 기존에 프로필 연결 없이 저장된 설정은 값을 보존한 프로필로 복구한다.
- 기본 프로필 지정은 이름과 별도로 표시한다. 모델 프로필도 기본으로 지정할 수 있으며, 이때 ID와 저장값을 유지한 채 모든 모델에서 사용할 수 있게 한다. 기본 지정 작업은 편집 중인 옵션과 프롬프트를 미저장 상태로 유지하며, 잘못 입력한 값과 오류 표시도 보존한다.
- 새 프로필로 저장하는 버튼은 상단에 하나만 표시하며, 입력창에서 공용·모델 사용 범위를 선택하고 ‘새 프로필 생성’으로 확정한다. 생성 후 현재 대상에 적용한다. 기존 프로필의 변경은 모든 화면에서 스크롤 중에도 보이는 프로필 영역의 ‘프로필 저장’ 버튼으로 저장하며, 저장 대상 이름을 함께 표시한다. 저장 후 편집 상태를 갱신하고 모달을 유지하므로 계속 수정하고 저장할 수 있다. 실행·재시작도 선택한 프로필을 먼저 저장한다. 다른 프로필을 미리보기만 하면 저장 대상은 바뀌지 않으며, ‘이 프로필 선택’으로 선택을 바꾼다. 이름 변경·삭제도 즉시 저장하므로 창을 닫아도 완료된 작업은 유지된다. 복원은 대상의 마지막 저장값을 다시 읽는다. 상단 닫기 또는 Escape로 창을 닫으며, 로딩 중의 취소 버튼은 실행 작업을 중단한다.
- 프로필 저장·적용·이름 변경·삭제가 성공하면 대상의 저장값을 다시 읽고 작업 중 편집값을 정리한다. 기본 프로필 지정은 편집값과 미저장 표시를 유지한다. 저장 실패 시에도 편집값을 유지한다.
- 공용·모델 프로필 모두 런타임·GPU·보조 모델·어댑터·추가 인수·시스템 프롬프트를 포함한 실행 옵션을 저장한다. 사용 범위만 다르며 공용 프로필은 다른 모델에서도 선택할 수 있다. 선택하거나 저장할 때 모델별 사본을 자동 생성하지 않고, 선택한 실제 프로필 ID를 유지한다. 이전 설정에 남아 있는 사본은 독립된 프로필로 표시하고 해당 프로필의 값만 수정한다. 옵션을 프로필에 저장하지 않고 모델에만 적용하는 경로는 제공하지 않는다. 엔진 로드 옵션은 모델을 다시 실행할 때 반영한다. 프로필 삭제 시 사용하던 대상의 설정과 프롬프트를 지정된 기본 프로필 값으로 전환한다.
- 프로필 저장은 다른 대상의 저장된 적용값이나 실행 중인 프로세스를 일괄 변경하지 않는다. 프로필을 명시적으로 선택하거나 모델·세션을 다음에 실행하면 프로필의 최신 저장값을 사용한다. 실행 중인 프로세스는 요청 설정을 명시적으로 갱신하거나 다시 실행하기 전까지 현재 값을 유지한다.
- 프로젝트와 벤치마크 설정도 프로필을 먼저 저장한 뒤 해당 편집기에 전달한다. 프로젝트의 시스템 프롬프트는 모델 설정의 프로필 안에서 수정·저장한다. 프로젝트는 저장·재열기·가져오기·내보내기 후에도 프로필 연결을 유지한다. 삭제된 프로필을 참조하는 프로젝트는 실행 옵션을 열거나 적용할 때 기본 프로필의 설정과 프롬프트를 사용하며, 삭제한 프로필을 다시 만들지 않는다.
- 개별 옵션 초기화는 해당 옵션을 런타임 기본값으로 되돌린다. 프로필 전체 초기화는 런타임·GPU 배치·보조 파일·어댑터·프롬프트를 포함한 모든 옵션을 초기화하며, 선택한 모델과 프로필 연결은 유지한다. 초기화한 값은 프로필을 저장해야 유지된다.
- 현재 지원 플랫폼은 Windows x64이며, Linux와 macOS는 지원 계획에 포함된다.
