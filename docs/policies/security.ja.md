## 報告

公開 issue を作成しないでください。[GitHub Security Advisories](https://github.com/aiolm/AioLM/security/advisories/new) を使用するか、メンテナーに非公開で連絡してください。最小の再現を含め、シークレットは `[REDACTED]` に置き換えてください。

## 対象範囲

ランタイムアーカイブ検証、パストラバーサル、PR ソースビルドの来歴、プロセスライフサイクル、ローカルエンドポイントの公開、インストーラー整合性、Tauri capabilities。

## ローカル認証

デスクトップ管理のモデルプロセスは `127.0.0.1` の内部用ポートにバインドされ、起動ごとに一時的な `--api-key-file` を通じてベアラートークンを渡します。一時ファイルは起動後に削除され、トークンはモデル停止時にクリアされます。独立して制御する外部 API も `127.0.0.1` にバインドされ、モデル交換や API の停止・起動にかかわらずアプリ終了まで有効な別のメモリ内キーを使います。同じ Windows ユーザー権限のプロセスはこれらのサービスを検査または操作できる場合がありますが、これは想定内です。エンドポイントやキーを共有しないでください。

ヘッドレス CLI の `server start` モードは異なります。このモードは意図的に `--no-api-key` を使用し、`127.0.0.1` バインドに依存します。そのポートにアクセスできるローカルプロセスは呼び出せるため、信頼できる PC だけで使用し、ポートを外部公開・転送しないでください。

API サーバーもローカル専用です。MCP サーバーはユーザー権限で起動する第三者の実行ファイルなので、信頼できる実行ファイルだけを追加し、設定した承認ポリシーに従ってツール呼び出しを確認してください。

MCP サーバーの初回起動には、コマンド、引数、許可リストに従って継承する環境と作業ディレクトリに結び付いたネイティブ OS 承認が必要です。これらの実行入力が変わると再度確認します。承認のフィンガープリントは編集可能なサーバー一覧ではなく、Rust が管理する別のデータファイル `mcp-launch-approvals.json` に保存されます。ツール呼び出しの承認は別途必要です。

## ネットワークリダイレクト

ランタイムの GitHub・Hugging Face リクエストは、各リダイレクトで HTTPS と信頼できるサービスホストを要求し、最大 10 ホップに制限します。GitHub メタデータには GitHub ホストの許可リスト、ランタイムと検証モデルの転送には信頼できるダウンロードホストを使用します。最終応答の URL も検査します。最初の URL が許可されていても、信頼できないホストを経由したり HTTP に切り替えたりすることはできません。

## 事前ビルド済み PR アーティファクト

ポータブル ZIP とワークフローで公開された CPU アーティファクトは、platform/arch/backend/build-id、GitHub アセット SHA-256、ファイル単位マニフェスト SHA-256、埋め込み PR リポジトリ/コミット、必須実行ファイル、正常なプレフライトを検証します。受信 PC は CMake/コンパイラ/SDK 不要ですが、GPU ランタイムは互換 GPU ドライバーが必要です。ワークフローは既定で CPU のみを公開し、GPU は SDK 搭載マシンからエクスポートする必要があります。

## ソースからの PR ビルド

第三者のコードをユーザー権限でコンパイルします。ダウンロード前に来歴（タイトル/作成者/リポジトリ/ブランチ/コミット/状態）を表示し、そのコミットに固定 — head が移動した場合は拒否します。PR ソースアーカイブはコミット固定 HTTPS で取得し、期待されるコミットディレクトリを検査します。GitHub はそのソースアーカイブの信頼できるダイジェストを公開しないため、保存された SHA-256 はローカル監査記録です。リリースインストーラーは可能な場合 GitHub アセットのダイジェストを使用し、なければ `checksums.txt` を代替として使用します。チェックサムはファイルの整合性を確認するだけで、公開者を保証するものではありません。ビルドはアーカイブ内に限定（BoringSSL/libcurl/OpenSSL off）、2段階確認が必要、すべての PR 状態が明示されます。対応バックエンド: `cpu` `vulkan` `cuda` `rocm`（SYCL/OpenVINO は拒否）。

## 子プロセス環境

`llama-server`、`llama-bench`、CMake ビルドはクリアされた env + プラットフォーム別の明示的許可リストで実行されます。プロキシ/TLS 変数は企業ビルドのために渡され、シークレット（`GITHUB_TOKEN`、`*_TOKEN`、`*_PASSWORD`、`SSH_AUTH_SOCK` など）は除外されます。Git 認証情報ヘルパーは無効化されます。

## サポートバージョン

最新リリースと `main` が修正対象です。古いリリースはアップグレードが必要な場合があります。
